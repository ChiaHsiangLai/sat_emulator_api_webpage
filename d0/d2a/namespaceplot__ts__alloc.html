def plot_ts_alloc._read_frame_carrier_counts ( str  net_config_path)
private 
Parse Net_Configurations.txt and return (num_frames, carrier_counts),
computed the same way FrameConf::GetCarrierCount() does in the C++
simulator (model/frameConf.cpp): carrierCount = FrameXBandwidth /
FrameXCarrierBandwidth, for X in 0..FrameCount-1. This is the TRUE
physical frequency plan -- every carrier that actually exists for that
frame, regardless of whether this particular superframe happened to
allocate a slot on all of them.

Returns (None, None) if the file doesn't exist or is missing the keys
needed, so callers can fall back to auto-detecting from the data.

def plot_ts_alloc._read_superframe_duration_us ( str  net_config_path)
private 
Return Superframe0TargetDuration from the config, converted to µs.

The allocation records use microseconds for their start and duration
fields.  Keeping the plot extent tied to the configured superframe avoids
silently clipping slots when the simulation uses a duration other than
the former 100 ms plotting default.

讀取 TsAlloc + 各 UT request 檔案，繪製 MF-TDMA 時槽分配圖 (PNG + HTML)
carrier_bw_default: 每個 carrier 預設高度 (PNG y 軸單位)
ts_alloc_filename: 輸入檔名 (預設 "TsAlloc"；每個 superframe 的快照檔則是
                    "sf_<N>_TsAlloc"，見 plot_all_superframes.py)
output_prefix: 輸出 PNG/HTML 檔名前綴 (預設 "time_slots_alloc")
output_dir: PNG/HTML 輸出資料夾；預設 None 時沿用 files_dir (跟輸入檔案
            放在一起，維持原本行為)。想把結果圖跟原始資料分開放時指定
            這個 (見 plot_all_superframes.py 的 images_dir)，資料夾不存在
            會自動建立。
save_html: 是否額外輸出互動式 HTML；批次跑很多個 superframe 時關掉可以省時間
net_config_path: Net_Configurations.txt 路徑，用來取得每個 frame 真正配置的
                  carrier 數量 (frameCount 與 num_carriers 的預設來源) ——
                  這樣縱軸顯示的是完整的頻率分配，即使某個 carrier 在這個
                  superframe 裡完全沒有被分配到任何 time slot 也照樣顯示成
                  空白那一行，而不是被跳過。找不到檔案或缺欄位時，會自動
                  退回成從 TsAlloc 資料本身偵測 (原本的行為)。
                  num_frames/num_carriers 兩者「明確傳入的那個」一律優先。
sf_number: 目前這張圖對應的 superframe 編號 (由 plot_all_superframes.py
           從 "sf_<N>_TsAlloc" 這個檔名解析出來傳進來)。給了這個值時，
           Req 會去讀 BeamScheduler 為這個 superframe 另外存的
           "sf_<N>_UT_<addr>_reqPerRC_kbps" 快照，而不是那個每個
           superframe 都會被覆寫、只剩「最後一次」數值的原始
           "UT_<addr>_reqPerRC_kbps"——否則畫較早的 superframe 時，Req
           會顯示成整個測試跑到最後那一刻的值，不是那個 superframe 當時
           真正的請求量。維持 None 就是舊行為 (整個測試只有一份、一直被
           覆寫的檔案)，適合對整段 run 畫一張總圖的舊用法。
