Detailed Description

Render one time-slot-allocation PNG per superframe from a beam scheduler's
superframe_plots/ folder.

BeamScheduler::Schedule() (model/beamScheduler.cpp) writes one
"sf_<N>_TsAlloc" snapshot file per superframe into <beam scheduler log
dir>/superframe_plots/ -- same 7-field format as the whole-run "TsAlloc"
file plot_ts_alloc.py already reads, just scoped to a single superframe.
Rendering happens here, offline, deliberately separate from the live C++
scheduler thread: matplotlib/plotly rendering per superframe (potentially
hundreds of times over a run) is too slow to do inline in a thread whose
own timing this whole project has repeatedly had to protect.

Usage:
    python3 plot_all_superframes.py <superframe_plots_dir> [carrierKbps] [--html] [--net-config PATH]

<superframe_plots_dir> is the folder BeamScheduler wrote sf_*_TsAlloc files
into (e.g. log_file/NCC/Sat_1_beamScheduler_1/superframe_plots/). Rendered
PNGs (and HTML, if --html) go into an "images/" subfolder of it, kept
separate from the raw sf_*_TsAlloc / sf_*_UT_*_reqPerRC_kbps data files.
--html additionally writes the interactive Plotly HTML per superframe
(off by default -- hundreds of HTML files is usually more than needed;
pass it if you specifically want to hover-inspect a particular superframe).
--net-config PATH points at Net_Configurations.txt so the y axis shows
every configured carrier (default: "data/Net_Configurations.txt", i.e.
run this from the mininet-v2/ project root -- see plot_ts_alloc.py's
net_config_path for what happens if it can't be found).

num_frames/num_carriers default to None -- plot_ts_alloc() then prefers
the real per-frame carrier counts from net_config_path (the true
physical frequency plan, showing every configured carrier even if a
given superframe never allocated a slot on it) and only falls back to
auto-detecting from each superframe's own data if that file can't be
read. Either way beats plot_ts_alloc()'s own hardcoded defaults (1
frame, 4 carriers) -- a batch tool covering many superframes shouldn't
need the caller to already know FrameCount.
