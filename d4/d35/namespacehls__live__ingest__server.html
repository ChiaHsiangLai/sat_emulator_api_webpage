Detailed Description

hls_live_ingest_server.py — the uplink-push counterpart to plain
`python3 -m http.server`: instead of only serving GETs, this accepts POSTed
HLS segments and playlist updates from hls_live_push_client.py and re-serves
them over GET, so anyone watching the stream (e.g. ffplay pointed at this
server) sees exactly what has actually arrived so far — not what the origin
encoder has produced but hasn't reached here over the (possibly congested)
link yet.

Two POST endpoints:
  POST /segment/<name> — body is the raw .ts segment bytes, written to
                          <storage_dir>/<name>.
  POST /playlist        — body is the current full .m3u8 playlist text (the
                          push client always sends its complete, current
                          local copy, not a diff), overwriting
                          <storage_dir>/live.m3u8. This is deliberately the
                          *pushed* client's own view of the playlist, so a
                          viewer here only ever sees segments that have
                          actually finished uploading.

GET requests are served as plain static files out of <storage_dir> (same
convention as `python3 -m http.server`), so a client can fetch
live.m3u8/<segment>.ts exactly like any other HLS origin server.

One instance of this server is started per UE (see launch_uts_and_ues),
each on its own port and storage directory, rather than one shared
multi-tenant server for all UEs.

Usage:
    hls_live_ingest_server.py <port> <storage_dir>
