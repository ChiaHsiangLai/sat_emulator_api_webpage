Detailed Description

Monitor UE → UT L3 TX rate using an iptables OUTPUT byte counter.

Usage:
    ue_tx_monitor.py <ue_tx_path> <ue_tx_long_term_path> <duration_s>
                     <ncc_ip> <proto> <port> [<window_size>] [--sport]

<duration_s> <= 0 means "no limit": keep sampling until this process is
killed (e.g. by the test script's own end-of-run cleanup), rather than
stopping on a fixed timer. Useful when the UE's actual traffic can outlast
a fixed duration -- a hard cutoff would silently stop recording while the
UE keeps transmitting.

Installs a temporary iptables OUTPUT rule matching <proto> packets to
<ncc_ip>:<port> and reads its byte counter once per second.  The counter
reflects L3 bytes (IP header + transport header + payload) for the iperf
flow only — identical in accounting to ut_app_rx, which reads raw IP packets
from tun0 (Layer 3).

By default <port> is matched as the destination port (UE dialing out to a
port NCC listens on). Pass --sport when the UE is instead the server (e.g.
webpage's pull model, where NCC connects to a UE-hosted HTTP server): in
that case <port> is the UE's own listening port, so it shows up as the
*source* port on UE's outbound response packets, not the destination port.

ue_tx uses a rolling average over the last <window_size> seconds (default 1).
ue_tx_long_term uses the cumulative mean from the start.
Both files: <unix_timestamp> <kbps>.
