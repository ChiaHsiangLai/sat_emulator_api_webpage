Detailed Description

hls_live_push_client.py — the uplink-push counterpart to hls_live_client.py:
instead of a viewer pulling segments from a remote server, this simulates a
live broadcaster actively pushing its own growing HLS stream out to an
ingest server (python_tools/hls_live_ingest_server.py) as segments are
produced — the way a real streaming app (going live from a phone) initiates
the upload itself, rather than passively waiting for someone to connect in.

Reads the local HLS playlist directly off disk instead of fetching it over
HTTP — this runs on the same node as the ffmpeg -re live encoder (see
launch_live_video_encoder), so there's no need to round-trip a GET just to
discover which segments exist. As new segments appear, each is POSTed to
<ingest_base_url>/segment/<name>; after any successful push, a *synced*
playlist — built from only the segment names that have actually finished
uploading so far (see build_synced_playlist) — is POSTed to
<ingest_base_url>/playlist. This is deliberately NOT the same text as the
local playlist file: the local file can already list segments the encoder
has produced but this client hasn't gotten to (or failed to) push yet
— e.g. when push falls behind under a congested uplink and several
segments pile up between polls, or when <duration_s> is hit mid-batch —
and forwarding it verbatim would make the ingest server advertise segments
that 404 when a viewer actually requests them. #EXT-X-ENDLIST is only
appended once the local playlist has it AND every segment the local
playlist currently lists has been confirmed pushed.

PUSH LATENCY: each pushed segment's log line reports how far behind the
live edge the push itself finished — i.e. how much the uplink adds on top
of real-time production. This is (time push finished) - (segment file's
own local mtime, which is "when the encoder finished producing this
segment" since ffmpeg -re paces writes at real playback speed).

Runs until the encoder's playlist reaches #EXT-X-ENDLIST (and that final
playlist state has been pushed) or <duration_s> elapses, whichever comes
first. On exit, writes a small key=value summary to <summary_path>.

Usage:
    hls_live_push_client.py <local_playlist_path> <ingest_base_url> <duration_s> <summary_path>
    e.g. hls_live_push_client.py data/live_video_ue101/live.m3u8 \\
         http://10.0.255.254:5101 300 log_file/UE_10.0.200.101/video_live_push_duration.txt

def hls_live_push_client.build_synced_playlist (   playlist_text,
  pushed_set,
  append_endlist 
) 
Return a version of playlist_text containing only the header
directives plus #EXTINF/segment-name pairs for segments actually in
pushed_set, in their original order — so the ingest server never
advertises a segment that hasn't actually finished uploading (see the
module docstring for why the raw local playlist can't be forwarded
as-is). #EXT-X-ENDLIST is appended only if append_endlist is True.
